Reinforcement learning

Supervised learning uses examples that already have answers. Unsupervised learning looks for patterns without answers. In reinforcement learning, an agent tries something, sees what happens and gets a reward. Over time, it learns which choices tend to work.

Our agent is a penguin. It has to cross the lake to get a fish, without falling into a hole. At first, it has no idea where to go. Press Train and watch it learn from experience.

The basics

Agent and environment

The learner is the agent. The place it acts in is the environment. Here, the penguin is the agent and the frozen lake is its environment.

They take turns. The penguin sees where it is, picks a move, and the lake responds with a new position and a reward. Press Next to step through one turn.

The basics

State, action, reward

Each square is a state. The penguin's action is a move: left, down, right or up. The reward is 1 if it reaches the fish and 0 otherwise.

A trip from the start until it reaches the fish or falls in a hole is an episode. Try a few moves yourself. The penguin only gets a reward at the end if it reaches the fish.

The basics

Sooner is better

The agent wants to collect as much reward as it can. The total reward over an episode is called the return.

If the fish is five steps away, we would rather get it in five steps than in fifty. The discount, written γ (gamma), makes rewards count less when they are farther in the future. A reward one step away is multiplied by γ; a reward two steps away is multiplied by γ twice.

Use the slider to see how γ changes the value of the fish from each square.

Markov decision process

Markov decision process

A Markov decision process, or MDP, is a way to write down the rules of a problem like this lake.

It tells us which states and actions are possible, what can happen after each action, what reward the agent gets, and how much future rewards count. Once we know those pieces, we can use the same methods to solve a lake, a game or a robot's task.

StatesA square the agent can be in. The lake has 16.
ActionsThe moves it can choose: left, down, right or up.
TransitionsWhat can happen after a move, and the chance of each result.
RewardsWhat the agent gets. Here, reaching the fish gives 1.

The Markov property

The Markov property says the current state has enough information to make the next decision. Once we know the current square and the action, we don't need to know how the penguin got there.

For example, a penguin on square 9 has the same possible moves whether it arrived from above or from the side. In the examples on the right, ask: would knowing the past change what happens next?

Policies and values

Policy

A policy is the agent's plan. It tells the agent which action to take in each state. On this lake, we can draw the policy as one arrow in every square.

The goal is to find the policy that earns the most reward. That is the optimal policy. Turn the arrows and see if you can make a route to the fish.

Policies and values

Value

The value of a state is the return the agent expects if it starts there and follows its policy. A square near the fish is worth more than one far away, because the agent can reach the reward sooner.

Change the arrows to change the policy. The values update with them, so you can see which routes are better.

Policies and values

The Bellman equation

State values are connected. If a move gives a reward now and leads to a valuable state, then the square you started from should be valuable too.

value = expected(reward + γ × next-state value)

This relationship is the Bellman equation. Click a square to see how its value comes from the next move. The same idea is used by the algorithms in the rest of the lesson.

Algorithms

Planning or learning

How we solve the lake depends on whether we know its rules.

If we know what each move can do and how likely each result is, we can calculate a good policy before the penguin moves. That is planning.

If the rules are unknown, the agent has to try moves and learn from the rewards it gets. That is what Q-learning and SARSA do.

Algorithms

Value iteration

Value iteration is a planning method. It starts by giving every square a value of 0. Then it revisits each square and asks: if I choose the best move from here, what reward should I expect?

value = best action's expected (reward + γ × next-state value)

Each sweep passes information about the fish back to the squares that can reach it. Once the values stop changing, the agent can choose the move with the highest value in each square. Step through a few sweeps and watch the values spread.

Algorithms

Value iteration in Python

The code uses the MDP's transition rules to calculate the value of each move. For a slippery move, it averages over all possible results, weighted by their chances.

Each sweep updates the state values. At the end, the policy picks the move with the highest value. The arrows on the fish and holes don't matter: the episode ends there.

Algorithms

Q-values

Value iteration can look ahead because it knows the transition rules. An agent learning by trial and error does not have that information; it only sees the result of the move it just made.

It can still keep a value for each state and action. That estimate is called a Q-value. It answers: if I take this action here, how much reward can I expect from now on?

Once the estimates are useful, the policy is simple: choose the action with the highest Q-value.

Algorithms

Q-learning

Q-learning starts with every Q-value at 0. After a move, it updates the value for that state and action. It uses the reward it just got and its best estimate for the next state.

target = reward + γ × best Q in next state
new Q  = old Q + α × (target − old Q)

α (alpha) is the learning rate. It controls how much the new estimate changes. With α = 0.5, the value moves halfway toward the target on each update. Finish an episode, then run 1,000 episodes and watch the values spread back from the fish.

Algorithms

Explore or exploit

While it learns, the agent has to choose between using what it knows and trying something new.

  • Exploit: take the action with the best Q-value so far.
  • Explore: try a random action, which might reveal a better route.

Epsilon-greedy controls this choice. With chance ε, the agent explores; otherwise it exploits. Starting with a high ε gives it room to explore. Lowering ε later lets it use what it has learned.

Algorithms

SARSA

SARSA is another way to update Q-values. It is close to Q-learning, but the two methods make a different assumption about what the agent will do next.

Q-learning updates toward the best possible next action. SARSA updates toward the action the agent actually takes, including a random move during exploration.

In this cliff example, each step costs 1 and falling costs 100. Both agents explore 10% of the time. Notice how that risk changes the route SARSA prefers.

Q-learning: reward + γ × best Q in next state
SARSA:      reward + γ × Q of the next action

Q-learning assumes the agent will take the best action next. SARSA uses the action the agent really takes next, even when it is a random one.

Here each step costs 1 and falling off the cliff costs 100. Both agents make a random move 1 time in 10.

Algorithms

You get what you reward

The agent follows the reward, not what we meant. If the reward leaves out something we care about, it may learn a way to score well that looks wrong to us.

In a boat-racing game, an agent earned points by hitting targets. It found a spot where the targets kept coming back and circled there instead of finishing the race. When an agent behaves strangely, check what the reward is asking it to do.

Bigger problems

Deep Q-learning

A Q-table needs a row for every state. Sixteen rows are fine for this lake, but a game screen can have millions of possible states. Go has more board positions than there are atoms in the universe.

Deep Q-learning uses a neural network instead of storing one row for every state. The network takes in a state and estimates a Q-value for each action. DeepMind used this approach to learn Atari games from screen pixels; the network is called a deep Q-network, or DQN.

Bigger problems

Policy gradients

Q-learning estimates how good each action is, then chooses the action with the highest value. Policy gradient methods learn the policy directly. The policy gives each action a probability.

After a good episode, the method makes the actions it took more likely. This is useful when there are too many actions to compare in a table, such as the many possible joint movements of a robot. PPO is one popular policy-gradient method.

In the animation, a wider arrow means that move is more likely.

Bigger problems

Three kinds of learning

Reinforcement learning is useful when a program makes a series of choices and gets feedback about how well they went, but we can't label the right choice at every step.

It takes many attempts to learn. That makes it a good fit for games and simulations, where trying again is cheap. Which kind of learning fits each example?
