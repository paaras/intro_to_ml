Supervised learning

Supervised learning means learning from examples where the right answer is already known. Each example has some inputs and the answer that goes with them, and the model's job is to learn how to get from the inputs to the answer.

The inputs are called features and the answer is called the target, or sometimes the label. Once the model has learned from enough examples, you give it new inputs without an answer and it predicts one.

It's called supervised because the answers act like a teacher. The model can check its guesses against them while it learns. Last week's pets were a supervised problem too, since we knew which ones had been adopted.

Try being the model. Look at the examples, then guess the three new students.

 

Regression and classification

Supervised problems come in two kinds, depending on what the target looks like.

If the target is a number that can be anything on a scale, like a price or a temperature, it's a regression problem.

If the target is one of a few fixed groups, like pass or fail, or cat, dog or rabbit, it's a classification problem.

The quickest test is to ask whether an answer can be "a bit more" than another one. A price of 210 is a bit more than 200, so that's regression. A cat isn't a bit more than a dog, so that's classification.

What kind of answer does each question need?

Linear regression draws a straight line



  

    

      
Linear regression predicts the target with a straight line. For one feature the line is

    

    
price = m * size + b

    

      
m is the slope. It says how much the price goes up for each extra square metre.

      
b is the intercept. It's where the line starts, the price the line gives for a size of 0.

      
To predict the price of a house, find its size on the bottom axis, go up to the line and read off the price. Move the sliders until the line runs through the middle of the dots.

    

  

  

    

    

    

    
 

  










Measuring how wrong a line is



  

    

      
To pick the best line we need a way to score a line. We start with the error for each house:

    

    
error = actual price - predicted price

    

      
On the plot, each error is the red gap between a dot and the line. Dots above the line have a positive error, dots below have a negative one.

      
Adding the errors up seems like an obvious score, but it doesn't work. Positive and negative errors cancel out, so a line that misses badly in both directions can still add up to about 0. Try to find a bad line with a total near 0.

    

  

  

    

    

    

    
 

  










Mean squared error



  

    

      
The fix is to square every error before adding them up. A square is never negative, so nothing cancels out.

      
Then we divide by the number of houses to get the average. This is the mean squared error, or MSE. The lower it is, the better the line.

    

    
MSE = average of (error * error)

    

      
Squaring has a second effect. An error of 10 becomes 100, but an error of 40 becomes 1600. Big misses count much more than small ones, so the best line tries hard to avoid them. The red squares on the plot show this, each one is an error squared.

    

  

  

    

    

    

    
 

  










Fitting finds the line with the lowest MSE



  

    

      
Training a linear regression model, also called fitting it, means finding the values of m and b that give the lowest possible MSE on the training data.

      
You've been doing this by hand with the sliders. The computer does the same job with some maths that lands on the exact best answer straight away, so there's no guessing involved.

      
Get your MSE as low as you can, then press the button to see how close you got.

    

  

  

    

    

    

    

  










Training data and test data



  

    

      
A model always looks good on the data it learned from. What we actually care about is how well it does on houses it has never seen.

      
So before training, we hide some of the rows. The model learns only from the rest, the training data. Then we check its predictions on the hidden rows, the test data.

      
It's like a student studying past exam papers. Doing well on papers they've already seen proves very little, the real test is a paper they haven't seen before.

      
A common choice is to keep 20% of the rows for testing. Each time you split, the rows are picked at random.

Measuring a regression model



  

    

      
MSE is good for fitting, but hard to read, because it's in squared units. These three are easier to make sense of:

      
    
        
  • MAE, mean absolute error, is the average size of a miss, ignoring whether it's too high or too low. It's in the same units as the target, so an MAE of 18 means the predictions are off by about $18,000 on average.
    • 
        
  • RMSE is the square root of MSE. It's also in the target's units, but like MSE it counts big misses more, so it's always at least as big as MAE.
    • 
        
  • R² compares the model to the laziest possible guess, predicting the average price for every house. 1 is perfect, 0 is no better than the lazy guess, and below 0 is worse.
    •

Using more than one feature



  

    

      
With two features, the model learns one slope for each feature, plus the intercept:

    

    
price = m1 * size + m2 * age + b

    

      
Each slope says how much that feature changes the price when the other one stays the same. Here, each extra square metre adds about $1,900, and each extra year of age takes off about $1,600.

      
The code is the same as before, you just put more columns in X. Adding age takes R² from 0.93 to 0.99, because age explains a lot of what size couldn't.

    



    
model.score gives R² for a regression model.

Predicting a category



  

    

      
Now for classification. exams.csv has 40 students, the hours each one studied, and whether they passed. Passed is stored as 1 for yes and 0 for no.

      
Every dot sits on either 0 or 1, since you can't half pass. Press the button to try fitting a straight line through them anyway.

      
The line keeps going forever in both directions. For a lot of students it predicts numbers below 0 or above 1, which don't mean anything as an answer to "did they pass?".

      
What we'd like instead is something that always stays between 0 and 1, so we can read it as the chance of passing.

    

  

  

    

    

    
 

  










The sigmoid function



  

    

      
The sigmoid function takes any number and squashes it to somewhere between 0 and 1.

    

    
sigmoid(z) = 1 / (1 + e^-z)

    

      
You don't need to remember the formula, just its shape. Big positive numbers come out close to 1, big negative numbers come out close to 0, and 0 comes out as exactly 0.5.

      
However far you drag the input, the output never goes past 0 or 1. That makes it perfect for turning any number into a probability.

    

  

  

    

    

    
 

  










Logistic regression



  

    

      
Logistic regression takes the straight line from linear regression and passes it through the sigmoid:

    

    
z = m * hours + b
chance of passing = sigmoid(z)

    

      
The line can still give any number, but the sigmoid turns it into a chance between 0 and 1, which bends the line into an S shape.

      
Moving m changes how steep the S is. Moving b slides it left or right. Fitting works like before: the computer finds the m and b whose curve matches the dots best.

      
Despite the name, logistic regression is used for classification. The name comes from the line it uses inside.

    

  

  

    

    

    

    

    
 

  










From a chance to a decision



  

    

      
The model gives a chance, but often we need a yes or no answer. To get one, we pick a cutoff called the threshold. If the chance is at or above the threshold the prediction is 1, otherwise it's 0.

      
The usual threshold is 0.5, so anyone more likely to pass than fail gets predicted as a pass.

      
Moving the threshold moves the point on the hours axis where predictions flip from fail to pass. A higher threshold means the model needs to be more sure before it says pass.

Accuracy and its trap



  

    

      
Accuracy is the share of predictions that were right. It's the first score most people reach for, and often it's fine.

      
But picture a test for a disease where only 5 people in 100 are sick. A "model" that says healthy to everyone, without looking at anything, is right 95 times out of 100. That's 95% accuracy, and it never finds a single sick person.

      
Now compare it to a real test that finds 4 of the 5 sick people, but also wrongly flags 6 healthy ones. Its accuracy is lower, yet it's the only one of the two that's actually useful.

      
When one group is much rarer than the other, accuracy on its own can't tell you whether the model is any good.

The confusion matrix



  

    

      
A confusion matrix counts every combination of what really happened and what the model predicted. With two classes there are four boxes:

      
    
        
  • True positive: passed, and we predicted pass.
    • 
        
  • True negative: failed, and we predicted fail.
    • 
        
  • False positive: failed, but we predicted pass.
    • 
        
  • False negative: passed, but we predicted fail.
    • 
      

      
Positive means the class we're looking for, which is 1. True or false says whether the prediction was right. The two red boxes are the mistakes.

      
Tap a box to find those students on the plot, and move the threshold to see the counts change.

    

  

  

    

    

    

  










Precision and recall



  

    

      
Two scores focus on the positive class, and each one answers a different question.

      
Precision: of everyone we predicted would pass, how many actually did? It goes down when there are lots of false positives.

      
Recall: of everyone who actually passed, how many did we predict? It goes down when there are lots of false negatives.

      
Which one matters more depends on which mistake costs more. A spam filter needs high precision, because sending a real email to spam is worse than letting one spam email through. A disease test needs high recall, because missing a sick person is worse than a false alarm that a second test can clear up.

    

  

  

    

    

    

  










The threshold tradeoff



  

    

      
The threshold lets you trade precision for recall.

      
Lower it and the model says pass more easily. It catches more of the students who really passed, so recall goes up, but it also says pass to more who failed, so precision goes down.

      
Raise it and the opposite happens. The model only says pass when it's very sure, so those predictions are usually right, but it misses more of the real passes.

      
There's no threshold that's best for every problem. You pick it based on which mistake you'd rather make.

    3.
