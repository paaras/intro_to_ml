Many models are better than one

Every model so far has been a single model making a single prediction. This week we train lots of models and combine their answers, which is called an ensemble.

Then we'll look at Naive Bayes, which isn't an ensemble, just one more model to know. It's quick and especially good with text.

Ensembles

Asking a crowd

A crowd only helps when its members make different mistakes

Say you ask 51 people a yes or no question, and each one is right 60% of the time. If they answer on their own, the majority is right about 93% of the time, because it's unlikely that more than half of them are wrong at once.

But if everyone copies one person, the crowd is no better than that one person

Bagging

One tree changes a lot

Here a tree with no depth limit is trained on 45 of the 60 fruits, picked at random. Every time you train it on a different 45, you get a different tree, and sometimes even a different first question.

A model that changes a lot when the training data changes a little has high variance. Deep trees have high variance. We'll put that to use next, since trees trained on different samples make different mistakes.

Bagging

Bootstrap samples

To get different trees we need different training sets, but we only have one. A bootstrap sample picks 60 fruits from our 60 at random, putting each fruit back before picking the next, so the same fruit can come up more than once.

Some fruits get picked two or three times and others don't get picked at all. On average about a third get left out.

Bagging

Let the trees vote

Train a tree on each bootstrap sample and let them vote

This is called bagging, short for bootstrap aggregating. Each tree still overfits, but they all overfit in different ways, so when they vote most of those mistakes cancel out.

The accuracy below comes from cross-validation. It goes up quickly at first and then levels off. More trees won't make it overfit, because each new tree is just one more vote, and after a while the result of the vote stops changing.

Random forests

Random questions too

Bagged trees still look a lot alike. Every question gets to choose from all the features, so the strongest ones keep winning, especially near the top of the tree.

A random forest is bagging plus one more rule. Every time a tree asks a question, it can only choose from a few features picked at random for that question. In scikit-learn that's max_features.

On their own the trees get a little worse, but they're more different from each other, so the vote is usually better.

Here the trees use width, height and weight, and the forest gets 1 random feature per question. The bars show which feature each of 50 trees asks about first.

Random forests

Random forests in scikit-learn

n_estimators is the number of trees, and max_features is how many features each question can choose from. Forests are made of trees, so they don't need scaling.

Each tree leaves out about a third of the fruits, and those fruits can be used to test it. With oob_score=True you get this out-of-bag score for free. You'd still keep a test set for the very end, but the out-of-bag score is handy for trying settings.

feature_importances_ adds up how much each feature's questions cut down the mistakes in all the trees, and the numbers add up to 1

Boosting

Learning from mistakes

In a random forest the trees are trained separately, so none of them knows what the others got wrong. Boosting trains them one after another instead, and each new model pays more attention to the fruits the earlier ones got wrong.

This version is called AdaBoost. Each round adds a stump, a tree that only asks one question. After each round, the fruits it gets wrong get more weight, and they're drawn bigger. More weight works like having extra copies of that fruit, so the next stump cares more about getting it right.

One stump is a weak model, but the stumps vote together, and the ones that made fewer mistakes get a bigger say

Boosting

Fixing what's left

The most popular kind of boosting is gradient boosting. To see it, we'll predict a number, the bikes rented on a day from the temperature. More people ride when it's warm, but fewer when it gets too hot.

A tree can predict a number too, since each leaf can just give the average of the training days that end up there.

Gradient boosting starts by predicting the average for every day. Then it trains a small tree on what's left over, the difference between the real number and the prediction, and adds that tree's guess on. The next tree works on whatever is still left over, and so on.

The dashed orange line is what the next tree will add. The name “gradient” comes from the math behind finding what's left over.

Boosting

Small steps

Adding all of each tree's guess can overshoot, so it gets multiplied by the learning_rate first. With 0.1, each tree only fixes a tenth of what it thinks is left over. Smaller steps need more trees, but usually do better on new data.

Unlike bagging, boosting can overfit if you keep adding trees. Once the real pattern is learned, the new trees start chasing the noise in the training data, so the training error keeps going down while the test error starts creeping back up.

Cross-validation is how you choose the number of trees and the learning rate

Boosting

Boosting in scikit-learn

For classes, gradient boosting works with the probability instead of a number of bikes. The real answer is 1 for a lemon and 0 for an orange, and each tree works on what's left over between that and the predicted probability.

GradientBoostingClassifier takes n_estimators, learning_rate and max_depth, and the trees are usually small, with a depth of 2 to 5.

On big datasets, HistGradientBoostingClassifier does the same thing much faster by sorting each feature into bins first, like a histogram. By default it won't make a leaf with fewer than 20 rows, so on 60 fruits it does worse. You'll also hear about XGBoost and LightGBM, which are separate libraries for gradient boosting. For tables of data, one of these is often the most accurate model you can get.

Ensembles

Bagging or boosting?

Bagging fixes models that change too much, and boosting fixes models that are too simple

A model with high variance changes a lot with the training data, like a deep tree. A model with high bias is too simple to fit the pattern, like a straight line through a curve or a single stump.

Making a model more complex lowers its bias but raises its variance, and that's called the bias-variance tradeoff. Ensembles are one of the best ways around it.

Naive Bayes

A spam filter that counts words

Naive Bayes works in a completely different way. It's been used to filter spam since the 1990s, so we'll start there.

The training data is 20 text messages, 8 spam and 12 real. To learn, Naive Bayes just counts how many spam messages and how many real messages each word shows up in.

Click a word to see its counts

scikit-learn counts every time a word shows up, so “free free” counts twice. Counting messages is simpler to follow, and the idea is the same.

Naive Bayes

Each word changes the odds

Naive Bayes works with odds, spam compared to real, instead of spam out of everything. We have 8 spam and 12 real messages, so before reading anything the odds are 8 to 12, or 0.67. This starting point is called the prior.

Then each word multiplies the odds by how much more common it is in spam. If a word is in half the spam messages and a sixth of the real ones, it's 3 times as common in spam, so the odds get multiplied by 3.

At the end, odds of 3 (3 to 1) become a probability of 3 ÷ 4 = 75%. This is Bayes' rule.

In the counts on the right, each count has 1 added and each total has 2 added, which is explained in two slides


    

    

  










Naive Bayes


Why it's called naive



  

    

      
Naive Bayes treats every word as a separate clue, as if knowing one word tells you nothing about the others. That's not true. “claim” and “now” show up together all the time, so they're really one clue counted twice.

      
The button takes this to the extreme by counting “free” over and over.

      
Counting the same clue again pushes the probability toward 0% or 100% very fast. So don't trust the exact percentages it gives you, but its answer, spam or not, is usually still right.

    

  

  

    

    

    

    

  










Naive Bayes


A word that never showed up in spam



  

    

      
This message looks like spam, but “home” was never in a spam message, so with plain counts its ratio is 0. Anything times 0 is 0, so one word overrules all the others.

      
The fix is to pretend there's one extra message with the word and one without, in both spam and real. That adds 1 to every count and 2 to every total, so no word is ever 0. This is called smoothing, and in scikit-learn it's alpha, which is 1 by default.

    

  

  

    

    
Message: “Call now for free home delivery”. “delivery” wasn't in any training message, so the model has nothing to go on and skips it.

    

    

    

  










Naive Bayes


Naive Bayes with numbers



  

    

      
Width and height aren't words, so we can't count them. Gaussian Naive Bayes fits a bell curve to each feature for each class instead, like the widths of the lemons and the widths of the oranges.

      
For a new fruit, it checks how high each curve is at that fruit's width and height. Then it gives each class a score by multiplying how common the class is by those two heights, and the biggest score wins. This works with any number of classes.

      
It's still naive, since it looks at width and height separately

Which would you try first?



  

    

      
Naive Bayes is fast, works with little data and handles thousands of word columns. Random forests do well without much tuning. Boosting is often the most accurate on tables, but it takes some tuning.

      
There's often more than one good answer, so look at the reason after you pick
