Machine learning learns from examples

With normal programming, you write the rules yourself. In machine learning you hand the computer lots of examples instead, and it works out the rules on its own.

Say a shelter wants to know which pets are likely to get adopted. We could show a model a long list of past pets, each with its age, its species and whether it found a home, and it would pick up the patterns, like younger pets getting adopted more often.

That list of examples is the data, and everything the model knows comes from it.

 

A model only knows what the data shows

A model has no idea what a pet actually is. If the data says a dog weighs 2.8 kg when it really weighs 28, the model believes it, and what it learns gets bent around that mistake.

The line on the right is what a simple model learns about age and weight. Add the typo and watch how far one bad value drags the whole line.

This is why so much of machine learning happens before any model is trained, in getting to know the data and fixing what's wrong with it.

 

Exploring and cleaning

Getting to know a dataset is called exploratory data analysis, or EDA for short. It just means looking at the data from a few different angles until you understand what's in it and whether you can trust it.

Exploring almost always turns up problems, like missing values, typos and numbers that can't possibly be right. Fixing them is called cleaning. The two go together, since you look, find something, fix it, and then look again.

Try it on the table. There are 5 problems hiding in these 6 rows, see how many you can spot.

 

Most data comes as a table

Data comes from all over the place, like school records, shop sales, weather stations and game leaderboards. Very often it ends up in the same shape, a table where each row is one thing and each column describes it.

When people want to share a table, the most common way is a CSV file. Pretty much every tool can open one and save one, which is why it's the first format you'll learn to work with.

Press the button to see what these tables look like saved as CSV.

A CSV is just text

Open a CSV file in a text editor and you won't see a grid at all, just lines of text. CSV stands for comma separated values. Each line of the file is one row, and the commas mark where one column ends and the next one starts.

The first line is special because it holds the column names. And when a value is missing, you'll see two commas with nothing between them.

For the rest of these slides we'll use pets.csv, a small file about animals at a shelter. It has a few problems hidden in it on purpose, and by the end you'll have found and fixed every one of them.

Rows and columns

Once a CSV is loaded, it becomes a table. Each row is one pet, each column is one fact about every pet, like its age or its weight, and each box holds a single value.

The grey numbers on the left are the index, which is how pandas labels its rows. It starts counting from 0, so the first pet is row 0, not row 1.

Loading a CSV

pandas is the Python library people use for working with tables, and almost everyone imports it under the short name pd.

read_csv reads the file and hands back a DataFrame, which is just pandas' name for a table. We save it in a variable called df so we can keep working with it.

The file needs to sit in the same folder as your notebook. If it's somewhere else, you'll have to give the full path instead.

First look: head and shape

The first thing to do with any new file is simply look at it. df.head() shows the first 5 rows, which is usually enough to see what the columns are and what the values look like.

df.shape tells you how big the table is, written as (rows, columns).

You might notice that head() has brackets and shape doesn't. That's because head() is something the table does, while shape is just a fact it already knows about itself.

20 rows

What type is each column?

Next you want to know what kind of data each column holds. df.info() lists every column along with its type and how many values are actually filled in.

Numbers show up as int64 for whole numbers or float64 for numbers with decimals. Text shows up as object, or str in newer versions of pandas.

This matters because you can only do math on numbers. The price column looks like numbers to us, but the dollar sign makes pandas read it as text, so we'll need to fix that later.

Picking columns

A lot of the time you only care about one or two columns. Put a column name in square brackets, like df["age"], and you get just that column back.

To get several, you put a list of names inside the brackets, which is why you end up with double brackets: df[["name", "age"]].

A single column comes back as a Series, which is basically one column with its row numbers attached.

Click column names to pick them


    

  










Filtering rows



  

    

      
To keep only some of the rows, you start by asking a question about a column. df["age"] > 4 asks that question of every row and gets back True or False for each one.

      
Wrapping it in df[ ] keeps the rows that answered True and leaves out the rest. A row with a missing age always answers False, since there's nothing there to compare.

      
The same idea works with <, == for equal and != for not equal.

    



  

  

    

    

    

  










Quick stats with describe



  

    

      
describe() gives you a quick summary of a number column all in one go.

      
mean is the average, and 50% is the median, the value right in the middle once everything is sorted. 25% and 75% mark off the bottom quarter and the top quarter, and std tells you how spread out the values are.

      
Notice the mean is about 13 kg even though most of these pets weigh less than 6. Keep that in mind for the next slide.

    



  

  

    
Each dot is one pet's weight in kg, hover a row of the table

    

    

  










Mean vs median



  

    

      
The mean adds up every value and divides by how many there are, so every single value pulls on it. The median sorts the values and takes the one in the middle, so it only cares about order.

      
Try dragging one dot far to the right. The mean follows it, but the median barely moves, because the middle value is still in the middle.

      
That's why, when a column has a few extreme values, the median gives a more honest picture of a typical value than the mean does.

    

  

  

    

    

    

  










Counting categories



  

    

      
For text columns, the useful question is how many of each value there are. value_counts() counts them for you and sorts them from most to least common.

      
Look closely at the bars, though. Dog shows up four separate times, as Dog, dog, DOG, and "dog " with a space on the end. To a computer those are four different words, so we'll have to clean them up later.

Histograms show the shape of a column



  

    

      
A histogram shows the shape of a number column. It cuts the range into equal slices and draws a bar for how many values land in each slice.

      
Here you can see two clear groups, lots of small pets under 6 kg and a group of big dogs between 24 and 35 kg, with almost nothing in between. A single average would hide that completely.

      
The slider changes how many slices there are. pandas uses 10 unless you tell it otherwise.

    

    
df["weight"].hist()

Scatter plots compare two columns



  

    

      
A scatter plot puts two columns against each other. Each dot is one pet, placed by its age along the bottom and its weight up the side, which makes it easy to see whether two things are related.

      
Here something is clearly off. One pet sits way out at age 200 and squashes every other dot into a thin strip on the left. Hover the dots to find out who it is.

    

    
df.plot.scatter(x="age", y="weight")

  

  

    

    
 

  










Finding missing values



  

    

      
When a box in the CSV is empty, pandas fills it with NaN, short for not a number. It's pandas' way of saying there's nothing here.

      
df.isna() goes through the whole table and marks each missing box as True. Adding .sum() counts the Trues in each column, so you end up with the number of missing values per column.

      
Most models can't handle NaN at all, so every missing value has to be dealt with somehow. The next two slides show the two simplest ways.

    



  

  

    

  










Fix 1: drop rows with missing values



  

    

      
The simplest fix is to throw away any row that has a missing value, which is exactly what dropna() does.

      
pandas doesn't change df itself, it gives you back a new table, so we write df = df.dropna() to keep the result.

      
It's quick, but every dropped row is data you lose. Here that's 5 of our 20 pets, a quarter of the file, so this works best when only a few rows have gaps.

    



  

  

    

    

  










Fix 2: fill missing values



  

    

      
Instead of dropping rows, you can fill the gaps with a sensible guess. fillna() puts a value into every empty box of a column.

      
It helps to read the line from the inside out. First it works out the median age, and then it fills the empty ages with that number.

      
Try filling with the mean as well. Daisy's age of 200 drags the mean up to about 15, which is an odd guess for a pet, while the median stays at a sensible 4.

    

    
df["age"] = df["age"].fillna(df["age"].median())



  

  

    

    
 

    

  










Duplicate rows



  

    

      
Sometimes the same row ends up in a file twice, usually because data got copied and pasted or combined from two places. A duplicate counts that pet twice and quietly throws off everything else.

      
df.duplicated() flags every row that's an exact copy of an earlier one, and .sum() counts them. Then drop_duplicates() removes the copies and keeps the first.

    



  

  

    

    

  










Cleaning messy text



  

    

      
To fix the species column we need text tools that work on every value at once, and that's what .str gives you.

      
.lower() turns everything lowercase and .strip() cuts off any spaces at the start or end. Chaining them means each step works on the result of the one before it.

      
After both steps the four versions of dog become one, and the counts finally make sense.

    

    
df["species"] = df["species"].str.lower().str.strip()



  

  

    

    

    

  










Numbers stored as text



  

    

      
Every value in the price column starts with a dollar sign, so pandas treats the whole column as text, and you can't take the average of text.

      
We fix it in two steps. .str.replace("$", "") swaps each dollar sign for nothing, which leaves text that looks like a number, and .astype(float) then turns that text into actual numbers.

      
Click through the steps on the right to watch it happen.

    

    
df["price"] = df["price"].str.replace("$", "").astype(float)



  

  

    

    

    
 

  










Impossible values



  

    

      
Some values are wrong in a way no tool will flag for you, like a cat that's 200 years old. You only catch these by looking at the data, which is why the plots from earlier matter so much.

      
To find them, filter for values that can't be real, df[df["age"] > 30]. To get rid of them, keep only the sensible rows with df = df[df["age"] < 30].

      
One catch is that a missing age fails that check too, so those rows get dropped along with it. Fill the missing ages first if you want to keep them.

    



  

  

    

    

    
 

  










Dropping columns you don't need



  

    

      
Not every column helps a model. A pet's name doesn't tell you anything about whether it gets adopted, so to a model it's just noise.

      
df.drop(columns=["name"]) removes it, and the list can hold as many column names as you want to get rid of.

    



  

  

    

    

  










Making a new column



  

    

      
You can also build new columns out of the ones you already have. Assign to a column name that doesn't exist yet and pandas creates it for you.

      
The math runs on every row at the same time, so there's no need for a loop. If either value in a row is missing, the answer for that row is missing too.

    

    
df["price_per_kg"] = df["price"] / df["weight"]



  

  

    

    

  










Models only understand numbers



  

    

      
Models work with numbers, so a column full of words like cat and dog has to be turned into numbers somehow.

      
get_dummies does this by giving each category its own column. A pet gets True in the column for its species and False in the others, and models read those as 1 and 0.

      
Make sure you clean the text first, otherwise Dog and dog would each end up with a column of their own.

    

    
df = pd.get_dummies(df, columns=["species"])



  

  

    

    

  










Saving your clean data



  

    

      
Once the data is clean, save it so you never have to redo the work. to_csv writes the table out to a CSV file.

      
Add index=False, or pandas will also save the row numbers as an extra column with no name. And save it under a new name, so the original file stays exactly as it was.
